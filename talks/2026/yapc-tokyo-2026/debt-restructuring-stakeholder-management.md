# YAPC::Tokyo 2026 プロポーザル

## 基本情報

- **形式**: 20分トーク
- **対象レベル**: 初級から中級
- **カテゴリ**: ステークホルダーマネジメント、社内プラットフォーム開発

## タイトル

知人の債務整理で活きた、プラットフォーム開発のステークホルダーマネジメント

## 概要

社内プラットフォームの開発では、利用するプロダクトチーム、業務部門、運用を担う人など、異なる関心と制約を持つステークホルダーと向き合います。開発チームが立てた計画は、他のチームが自分たちの計画を立てる前提にもなります。何が決まっていて、何をまだ約束できないのか。誰と何を確認すれば、次へ進めるのか。こうした調整も、プラットフォームを開発する仕事の一部です。

私は、知人の債務整理を手伝う中で、普段の開発で培ったステークホルダーマネジメントの知見に助けられました。当事者や弁護士など、立場によって必要な情報や判断が異なり、確認事項も期限も複数ある状況です。そこで、ロードマップ、課題管理表、ステークホルダー一覧表を使い、関係者の目的や制約、未確定事項、次に取り組むことを整理しました。

本トークでは、その中で役立った三つの観点を紹介します。相手が次に何を判断するのかを捉えること。確定事項と未確定事項を分け、相手の判断に必要な形で伝えること。そして、対外的な期限から逆算し、確認や手戻りの時間を含めて内部の作業を小さく分けることです。それぞれについて、債務整理の支援で何が難しく、どう整理して次の行動につなげたのかを話します。

この経験は、日々のプラットフォーム開発で行っている調整の意味を見つめ直す機会にもなりました。こちらが説明を終えた時点で、相手は判断できる状態になっているか。こちらの見通しを、相手が確約として受け取っていないか。後半では、支援を通じて得た学びを、現在の社内プラットフォーム開発における対話やロードマップの共有にどう活かしているかを振り返ります。

仕事で得た知見を仕事の外で使い、そこでの学びをまた仕事へ持ち帰る。その往復から、複数の関係者と進める開発で、誰に何を確認し、どの段階で何を約束するかを考える視点を共有します。

## トーク構成

| 時間 | 内容                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------- |
| 2分  | 社内プラットフォーム開発で向き合う、関係者の目的・制約・計画の違い                             |
| 3分  | 知人の債務整理を手伝う中で、情報整理と関係者との調整が必要になった背景                         |
| 8分  | 三つの観点がどう役立ったか。関係者と判断の整理、未確定事項の伝え方、期限から逆算した作業の分解 |
| 5分  | 支援を通じて見つめ直したことと、現在の社内プラットフォーム開発での活用                         |
| 2分  | 聴衆が自分の案件で確認できる問いにまとめる                                                     |

## 対象聴衆

- 社内プラットフォームや共通基盤を開発し、利用チームや業務部門との調整を担っている人
- 複数チームが関わる開発で、未確定な計画の共有や期限の合意に悩んでいる人
- 技術者として仕事で培った知見と、仕事の外での経験のつながりに関心がある人

## 聴衆が得られるもの

- 関係者の肩書きに加えて、目的・制約・次に必要な判断を整理する観点
- 確定事項と未確定事項を分け、相手が次の行動を取れるように情報を伝える考え方
- 内部の作業計画と対外的な約束を分け、確認や手戻りの時間を組み込む考え方

## 補足

扱うのは、債務整理を手伝う立場で行った情報整理、連絡、作業計画と、そこから得た実務上の学びです。関係者は役割で説明し、個人や案件を特定する情報は掲載しません。表を用いる場合は、実際の資料から説明に必要な構造を取り出して再構成します。
