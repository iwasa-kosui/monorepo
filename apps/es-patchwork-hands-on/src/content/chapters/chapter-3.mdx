## 記録から答える

第2章を終えたディレクトリか `chapter-2-step-2` で、次のコマンドを実行します。

```bash
node who-cancelled.ts
```

`who-cancelled.ts` は、来院を2件用意して次の SELECT を実行します。`visits` と `domain_events` を来院の ID で結びつけます。

<CodeBlock code={whoCancelledQuery()} />

実行すると、次の表が出ます。`event_at` の値は実行のたびに変わります。

```text
┌─────────┬───────────────────────┬─────────────┬────────────────────────────┬──────────────────┬────────────────┬────────────────┐
│ (index) │ id                    │ status      │ event_at                   │ event_name       │ operated_by    │ reason         │
├─────────┼───────────────────────┼─────────────┼────────────────────────────┼──────────────────┼────────────────┼────────────────┤
│ 0       │ 'visit-after-events'  │ 'cancelled' │ '2026-11-06T09:54:48.407Z' │ 'VisitCancelled' │ '受付スタッフ' │ '飼い主の都合' │
│ 1       │ 'visit-before-events' │ 'cancelled' │ null                       │ null             │ null           │ null           │
└─────────┴───────────────────────┴─────────────┴────────────────────────────┴──────────────────┴────────────────┴────────────────┘
```

`visit-after-events` の行から、導入の問い合わせに答えられます。

| 問い | 列 | 答え |
|---|---|---|
| 誰が | `operated_by` | 受付スタッフ |
| いつ | `event_at` | 記録された時刻 |
| 何を | `event_name` | 来院のキャンセル |
| なぜ | `reason` | 飼い主の都合 |

## 導入前の過去は残らない

`visit-before-events` は、記録を足す前にキャンセルされた来院を表します。この行の記録の列は `null` です。記録を足しても、足す前の出来事は分かりません。

[関連記事](https://kosui.me/posts/2025/05/06/142842)は、「今記録できていないから今さらやっても仕方がない」という考えを捨てるべきだと書いています。記録を足した時点から先の変更には答えられるようになります。
